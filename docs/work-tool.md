# 業務秘書（/work）設計メモ

日々のタスク管理を、本人が「管理の仕組みを覚えなくても」回るようにするための業務管理ツール。
既存のめだか手帳（`/`）とは独立した画面で、PC ブラウザでの利用を前提にしています。

## 何を解こうとしているか

前提として、次の3つを設計の起点にしています。

1. **これまで自分でタスク管理をしてこなかった** → 分類ルールや運用手順を覚えさせない。
   走り書きを投げれば AI 秘書が構造化して登録するところまでやる。
2. **リマインドを設定するのが苦手** → 通知を「自分で仕掛ける」のではなく、
   画面を開いた瞬間に「今日やること」と「放置されているもの」が向こうから出てくる。
3. **スマホを普段見られない** → 通知に依存しない。ブラウザを開いた時点で状況が揃っている。

## 画面の構成

| 領域 | 役割 |
| --- | --- |
| 今日の作戦 | 採点順に並べ、その日の持ち時間に収まるぶんだけ提示する。理由も併記 |
| 気になっていること | 期限超過・先送り常習・長期放置を、その場で片付けられる操作つきで提示 |
| この先1週間の山 | 期限が固まっている日を可視化し、前倒しの判断材料にする |
| AI秘書 | 走り書きの投入口。登録・変更・相談をここで完結させる |
| すべてのタスク | 絞り込みと並べ替えつきの一覧 |

## 優先順位の決め方

`src/lib/work/planner.ts` の `scoreTask()` が決めています。AI には依存しません
（APIキーが無くても順位づけは動きます）。

- 期限超過: 100点 + 超過日数 × 8
- 今日が期限: 85点 / 明日: 45点 / 3日以内: 28点 / 今週中: 14点
- 重要: +32点 / 通常: +12点
- 着手済み: +18点
- **先送り回数 × 9点** — 何度も後ろに倒したものほど前に出す
- **14日以上動きなし: +22点** — 塩漬けを掘り起こす
- 15分以内で終わる: +6点

期限そのものより「放置され続けていること」を重く見るのが方針です。
期限を後ろにずらす操作（`postponeAction`）は先送り回数を加算するので、
逃げ続けているタスクは自動的に上へ上がってきます。

1日の持ち時間（既定 4 時間）に収まる範囲で上から詰め、溢れた分は今日の作戦から外します。
ただし今日が期限・期限超過のものは持ち時間に関係なく必ず入ります。

## AI秘書

- `src/lib/work/agent.ts`。Anthropic Messages API のツール実行ループ
  （`client.beta.messages.toolRunner`）を使用。モデルは `claude-opus-5`。
- 使えるツール: `create_tasks` / `update_task` / `complete_task` / `delete_task` / `list_tasks`
- APIキーは**サーバー側でのみ**参照します。ブラウザには一切渡りません
  （CSP の `connect-src` も `'self'` のみ）。
- **APIキーが無くても動きます。** その場合は `src/lib/work/offlineParser.ts` の
  簡易解析にフォールバックし、「明日」「水曜まで」「月末」「毎日」「至急」「2時間」などを
  読み取ってタスク化します。画面には「簡易モード」と表示されます。

## セキュリティ設計

| 項目 | 実装 |
| --- | --- |
| パスワード | scrypt (N=32768, r=8, p=1) + 16バイトソルト。平文は保存しない |
| パスワード照合 | `timingSafeEqual`。ユーザー名が違う場合もハッシュ計算を通す |
| セッション | HMAC-SHA256 署名つき Cookie。有効期限8時間 |
| Cookie 属性 | `HttpOnly` / `SameSite=Strict` / 本番は `Secure` + `__Host-` 接頭辞 |
| CSRF | SameSite=Strict に加え、`src/proxy.ts` で書き込み系リクエストの Origin を検証 |
| 総当たり対策 | 10分間に8回失敗でロックアウト（`src/lib/work/rateLimit.ts`） |
| 認可 | `src/lib/work/dal.ts` の `verifySession()` を全 Server Action の先頭で通す |
| セキュリティヘッダ | CSP / HSTS / X-Frame-Options / nosniff / Referrer-Policy（`next.config.ts`） |
| キャッシュ | `/work` 配下は `no-store`、`X-Robots-Tag: noindex` |
| データ保存 | `.data/` に 0600 で保存。一時ファイル + rename の原子的書き込み |
| 入力の正規化 | 保存前に制御文字を除去し、長さ・列挙値を検証（`src/lib/work/tasks.ts`） |

`proxy.ts`（Next.js 16 で middleware から改名）が行うのは早期リダイレクトと Origin 検証だけで、
本当の認可判定は必ずサーバー側の `verifySession()` で行っています。
Server Action は UI を経由せず直接 POST できるため、この二重化が必要です。

## 未対応 / 今後の検討事項

このたたき台では次を意図的に外しています。

- **単一ユーザー前提。** 従業員を増やす場合はユーザー管理と権限が必要です。
- **保存先が JSON ファイル。** 単一サーバーでの運用が前提です。複数インスタンスで
  動かす場合はデータベースへの移行と、ログイン試行回数の共有ストア化が必要です。
- **通知は画面内のみ。** 「スマホを見られない」前提から通知を外していますが、
  必要ならメールや Slack への日次サマリ送信を足せます。
- **2要素認証なし。** インターネット公開するなら、追加を推奨します。
- **監査ログなし。** AI秘書の操作履歴は会話ログに残りますが、直近60件のみです。
